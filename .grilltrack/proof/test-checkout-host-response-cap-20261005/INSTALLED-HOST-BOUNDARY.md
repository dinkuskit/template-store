# Concrete installed host boundary

Template owns the public demo routing and shopper UI. Current public Worker
rejects every POST, and the cart deliberately disables checkout. Once the
installed host is admitted, Template can add a narrow canonical prepare/start/
status surface and consuming shopper behavior while preserving admin protection.

The existing Registry Commerce entrypoint calls admitBoundGuestCheckoutRuntime
without trusted host options and declares no checkout cron hook. Its manifest
has no network capability/allowed hosts. EmDash1.0.1 supplies owner-scoped plugin
storage and cron context, but HTTP requires a declared capability and its public
PluginContext has no wired cross-plugin Payments invocation. A native entrypoint
can compose createPlugin({checkout}) outside JSON descriptor options, but that
is not actual Registry identity/storage/route proof.

The next source-owned handoff must provide a supported installed-Commerce
context path joining its existing guest routes and one cron handler to the
existing approved TEST broker/consumer, with canonical storage and associations.
Commerce owns this public seam; Template owns its host/site integration.
No private context factory, raw SQL, second order writer, global fetch bypass or
new permission/credential grant is introduced as a shortcut. If an additional
capability is required, its exact owner gate must be explicit.
